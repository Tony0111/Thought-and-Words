# 作品文件夹约定

`works/` 是唯一的作品区。**一个作品一个文件夹**，文件夹名就是作品名。
从素材到终稿都留在这个文件夹里，靠文件名前缀表示阶段，**不靠移动目录表示状态**。

```text
works/
└── <作品名>/
    ├── 00-素材与背景.md     # 征稿要求、原始素材、参考链接（可选）
    ├── 01-brief.md          # 写前 brief / 构思
    ├── 10-初稿.md           # 初稿
    ├── 11-初稿-B版.md       # 变体（换风格、换角度），编号顺延
    ├── 20-修订.md           # 二稿及以后（可选）
    ├── 80-终稿.md           # 定稿（发布用的那一版）
    ├── 81-发布记录.md       # 链接、发布时间、反馈（可选）
    ├── 90-创作分析.md       # 创作分析、复盘（可选）
    └── assets/              # 该作品用到的图片、GIF、PDF 等
```

## 命名规则

| 前缀 | 含义 |
|---|---|
| `00-` | 素材、征稿要求、背景资料 |
| `01-` | brief / 构思（写前） |
| `10-` | 初稿；变体用 `11-`、`12-`，名字里标版本 |
| `20-` | 修订稿 |
| `80-` | 终稿：真正发布出去的那一版 |
| `81-` | 发布记录：链接、时间、修改说明 |
| `90-` | 创作分析、复盘 |
| `assets/` | 二进制资源，不放正文旁 |

## 状态判断

不需要额外维护状态字段，看文件名即可：

- 只有 `01-brief.md` → 构思中
- 有 `10-初稿.md` / `11-…` → 在写
- 有 `80-终稿.md` → 已定稿（是否已发布看 `81-发布记录.md`）

同一篇要发到不同渠道且内容需要分叉时，另建 `82-终稿-公众号.md` 这类文件，仍留在同一文件夹。

## 约定

- 正文里的图片用相对路径，例如 `![](assets/image.png)`，保证在任意编辑器里都能显示。
- 文件名统一用 `-` 连接，不用 `_`。
- 整个 `works/` 已被 `.gitignore` 忽略：作品只在本地和同步盘里，不上传 GitHub。
